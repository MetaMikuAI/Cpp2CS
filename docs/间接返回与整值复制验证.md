# 间接返回与整值复制验证

## 核心行为

在[聚合值恢复](聚合值恢复验证.md)的基础上，继续连接大结构体的间接参数、x8 返回缓冲区和调用后的栈存储。

- 间接参数对应托管值参数的地址；输出仍按值传参，不把它改成 C# 的 `ref` 参数。
- 本方法的 x8 入口地址对应独立的返回局部值。读取和返回之前，所有路径都必须完成所需写入；不能依赖 CIL 的零初始化补齐原生漏写。
- 已知调用的间接返回先保存一次，再写入其真实目标区域。调用参数先读取，返回缓冲区后写入，即使两者地址相同也不能颠倒。
- 尾调用必须把入口返回缓冲区完整转交给被调用者。
- 栈对象检查负责范围、别名和初始化；具体语句的类型仍由托管恢复确认。未经恢复的宽读写不会因范围合法而自动通过。

`TypedCopies` 识别单个基本块内的整值复制：来源和目标各自连续、不重叠，所有来源片段先读完，随后写回；片段变量没有其他用途，区间内没有调用或其他副作用。两端必须对应同一种已知结构体。

满足条件时，在原来第一次读取的位置保存整个值，在第一次写入的位置复制保存值。这样可以恢复 128 位加 64 位等复制序列，又不会把结构体或对象引用当作整数拆开。该处理发生在托管恢复阶段，不改写机器 SSA。

尚未覆盖交错读写、带未知副作用的复制、未知地址别名、独立的宽向量计算、栈传参和异常区域。初始化检查目前也要求返回区域的填充字节已写入，存在保守拒绝。此实现不是完整内存模型。

## 真实样本

输入二进制和元数据哈希同[值布局验证](值布局验证.md)。

| 方法 | 地址 | 原生行为 |
| --- | --- | --- |
| `FieldCameraModel.get_LookAtBounds` | `0x56cb728` | 从 `this+0x58` 读取 24 字节，写入入口 x8 |
| `FieldCameraModel.set_LookAtBounds` | `0x56cb73c` | 从间接参数读取 24 字节，写入 `this+0x58` |

元数据确认该字段为 `UnityEngine.Bounds`。两个方法都先读取 16 字节和 8 字节，再完成写回；恢复后的 getter/setter 是普通的结构体字段读取和赋值。

执行测试使用真实恢复方法体。替代宿主只提供对应字段，Bounds 替代布局是六个连续浮点数；没有提供手写 getter/setter，也没有替代业务调用。覆盖零、负零、最小次正规数、正负无穷及 NaN 位型，并检查所有六个字段。没有加载 Unity 运行时。

合成执行检查另外覆盖三整数大结构体、含对象引用的结构体、直接返回写回、尾调用转交、两次调用复用栈缓冲区后的值快照。反例包括漏写、越界、单边初始化、循环首轮未初始化读取、重叠复制、交错读写、区间内未知调用和尾调用转交错误地址。

## 验证结果

| 项目 | 数量 |
| --- | ---: |
| `Sekai.Mysekai`、`Sekai.Api` 全部代码 case | 23,390 |
| 可形成托管方法体 | 8,498 |
| 写出 CIL 的目标 case | 8,155 |
| 相比 `e9d3a06` 新增 / 回退 | 37 / 0 |
| 尚未写出 CIL | 15,235 |
| 回读通过的方法定义，含访问器依赖 | 8,266 |

前后 case 集合完全一致。1,747 个目标源码文件中有 10 个变化，均属于 `Assembly-CSharp`。重新运行编译诊断后，1,701 个目标文件为零错误；主程序集仍有既有的两项范围外错误。其他四个程序集的 46 个目标源码文件逐字节未变。

`buffer-check`、`aggregate-check`、`body-check`、`stack-check` 通过。其余新增输出没有逐一执行，调用依赖也可能仍是骨架；输出数量不代表可运行的完整业务链数量。

证据位于 `artifacts/recovered-buffer-trial/`、`buffer-trial-bodies.log`、`buffer-final-check.log`、`buffer-aggregate-check.log`、`buffer-body-check.log`、`buffer-stack-check.log`、`compile-buffer-trial.log`。日志均在 `artifacts/` 下，生成物不提交 Git。
