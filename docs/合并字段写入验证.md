# 合并字段写入验证

## 恢复规则

- 按元数据和已知值布局，将一次 16、32 或 64 位写入对应到完整覆盖的数值字段；可经过基类及嵌套结构体路径。
- 支持对象字段、托管引用和已确定类型的栈对象。接收者和源值各求值一次，再从源位型提取字段值，保留原指令地址。
- 不跨填充，不切开标量，不解释重叠、未知偏移、引用或指针字段。静态合并写入及更宽的写入仍未支持。
- 布尔字段仅接受每字节为 `0` 或 `1` 的已知常量；其他位型和动态布尔打包需要额外证明。整数保留符号位，浮点使用位重解释。
- 现有单字段与完整结构体写入继续使用原路径。不能确定完整布局或源值时，整个方法保留诊断。

当前规则重建顺序字段赋值。跨线程观察原生宽写入的原子性尚未恢复，volatile、原子访问及 Unity 运行时行为不在本轮执行证据内。

## 执行验证

合成方法经过机器 IR、托管方法体、CIL、C# 重编译并执行，覆盖：

- 两个布尔字段的四种组合及范围外字段不变。
- byte、short、float 的合并写入，包括符号边界、负零、非正规数、无穷及 NaN 载荷；同时检查动态值和常量。
- 源值读取正在被写入的字段时，后续赋值仍使用写入前的值。
- 跨嵌套结构边界写入原托管引用，空对象仍抛异常。
- 填充、重叠、引用、未知偏移、部分标量和未证明的 bool 位型拒绝恢复。

真实 ARM64 方法 `PassRenderingSettings..ctor`（`0xa45dae0`）在 `0xa45dbd8` 将 `0x0101` 写入 `PassDepthSettings + 0x10`。元数据确认 `isActiveZWrite` 和 `isActiveZTest` 是偏移 `16/17` 的两个 bool。独立的 `PassDepthSettings..ctor` 位于 `0xa45dc24`。

这两个构造及 `PassBlendSettings`、`PassStencilSettings` 的真实恢复体通过 CIL/C# 执行：名称为 `BasePass`，颜色掩码为 `15`，深度布尔值为真、比较枚举值为 `4`，混合源值为 `1`，模板字段清零，重复构造使用独立对象。

`MaterialRenderingSettings..ctor`（`0xa45d4c8`）完整恢复体也通过 CIL 执行，验证队列值 `2000`、单元素通道数组及内部构造链。其数组字段初始化尚不能还原为合法 C# 构造语法，因此源码往返仅覆盖上述内层类型。宿主映射实际字段与枚举，没有手写替代恢复方法体，也没有加载 Unity。

既有构造初始化、真实 API 构造及构造委托 CIL/C# 回归通过。
