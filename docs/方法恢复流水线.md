# ARM64 方法恢复流水线

以方法为单位分析。ARM64 指令先转成统一的机器效果，普通方法、async 和循环分析消费同一套指令定义。async 额外识别状态机协议。

```mermaid
flowchart TD
    A[方法入口 + 匹配的元数据] --> B[Arm64MethodReader\n解码、FDE、LSDA]
    B --> M[Arm64Effects\n寄存器读写、位宽、访存、标志、调用]
    M --> C[MethodAnalysis\n类型绑定、控制流、SSA、调用语义]
    C --> D[普通业务体 SsaBodyRecovery]
    C --> E[AsyncBody / AsyncRecovery\n确认挂起、恢复和完成协议]
    D --> F[ManagedExpressionBuilder\n参数、字段、调用、值]
    E --> F
    F --> G[通用 Expression / Statement\nawait 是表达式节点]
    G --> H[SemanticWriter\n结构化分支和 C# 输出]
    D -->|尚未覆盖，记录原因| I[FunctionLifter / MachineProjection\n栈值、结构体、数组、循环投影]
    M --> I
    M --> L[LoopLifting\n读取集合、修改集合]
    L --> I
    I --> G
```

## 边界

- `Arm64MethodReader` 只缓存指令和函数范围。优先采用入口匹配的 FDE；缺失时仍使用相邻符号作为候选边界，不能据此认定整个 IL2CPP 区域连续。当前单方法上限为 16 KiB。
- `Arm64Effects` 是指令效果的唯一实现。操作数扩展、移位、W/X 与 S/D/V 位宽、成对访存、前后索引写回、比较标志都在这里定义。所有输入来自执行前状态，访存完成后提交写回。
- `NativeSsa` 只把机器效果绑定到 SSA 身份和 Phi；`MachineProjection` 把机器效果投影到已有的有类型值与语句，不再有独立的 ARM64 指令解释器。两者可以有不同的源码恢复覆盖，但不能各自猜测一条指令的含义。
- SSA 先为按需读取的寄存器分配身份，再用队列填充前驱和异常边，最后消除平凡 Phi。控制流长度不增加构图时的调用栈深度；循环回边仍引用同一身份。
- `Arm64Registers` 统一调用破坏和部分保存范围，`Arm64Calls` 统一 helper 参数摘要。循环活跃值来自机器效果与实际 ABI，包括 X29、X8 返回缓冲及尾调用参数；不返回的 helper 仍然读取参数。
- 指令写入的高位清零与 ABI 未定义的高位分开处理。未知指令破坏已知写目标与内存；未知调用使栈缓存失效，不能继续引用调用前的旧值。
- 回退路径的已知签名不代表调用没有存储副作用。传出栈地址、未确定的实参或未知返回缓冲会使栈缓存失效；可能逃逸的地址跨状态复制和分支合流保留，后续普通调用继续使缓存失效。已证明的纯字段构造、绑定到可变局部的值类型接收者和明确的 X8 返回缓冲使用各自的新存储身份。调用前的寄存器快照保留原值；返回缓冲的字段在加载时绑定类型，再执行机器位宽扩展。
- 未使用的入口参数由机器效果和实际调用 ABI 证明：被调函数不能在完整覆盖前读取原寄存器；未知指令、未知调用和未确认的局部异常区域均阻止证明。隐藏 MethodInfo 也适用此规则，不能仅因名称或显示时省略就假定不影响存储。
- `MethodAnalysis` 保存一次分析中的方法签名、控制流、SSA、调用解释和分派结果。嵌套分析保留传入的方法身份，不重新按地址选择其他签名。
- `MetadataReference.ValueType` 统一元数据槽的内容类型，供 SSA 与回退投影共用。字符串槽为托管字符串，方法槽为 MethodInfo；其他槽保留显式声明，缺少声明时保持未知，不能一律作为方法信息。
- `FunctionLifter` 按机器读取身份复用 SSA 已绑定的泛型上下文类型，并保留原字段读取及证据。未绑定的上下文继续按原布局处理，不能直接把 `MethodInfo` 的重叠存储认定为泛型槽。
- `ManagedTypeBindings` 在入口绑定参数和继承类型。元数据共享，每个方法的推断类型表独立；表达式恢复器与静态属性投影不跨方法复用可变状态。
- `HeaderLayout` 保留匿名聚合的完整声明，由 Clang 计算大小及外层字段偏移。匿名聚合内部成员用于收集编译依赖和检查 ABI 成员类别，不屏蔽同一结构体中的独立字段。所有叶成员均为已确认整数或指针时，按整体大小和对齐分类为普通聚合，覆盖嵌套、数组和 union；重叠字段的身份和活动成员仍保持未知，不能按声明顺序选择。浮点或混合重叠布局的 ABI 尚未支持。
- `ManagedExpressionBuilder` 不解码指令。它把 SSA 的业务值映射为表达式，按实际签名读取调用参数，只移除明确的 MethodInfo 隐藏参数。
- async 归约只处理协议与路径收缩。业务调用、字段写入、返回及 await 生成通用语句节点；单 await 构造模式也使用同一个输出器。
- 普通 SSA 和 async 业务体在原读取位置生成已绑定字段的快照，避免把读取推迟到后续调用或 await 之后。路径收缩后检查每次快照使用是否都经过定义；被协议区吞掉的读取不能成为未声明的变量。属性访问器内保留自己的后备字段，避免生成递归属性访问；存储和写屏障始终指向实际字段。
- 循环入口与回边的并行赋值建成后，Phi 通过公共表达式遍历统一降低。残留 Phi 保留前驱和值并报告未恢复；诊断文本及语句树不能将其丢弃或当作普通变量。
- 条件选择区分数值与托管引用。同类型引用和明确的空值保留对象身份；引用与未定整数混合时报告缺口，不生成整数强转。结构化条件的取反使用布尔值，保留浮点 NaN 下的分支含义。
- `NativeValues.ReferenceAs` 与 `JoinReferences` 统一条件选择、Phi、循环边及返回中的引用/空值转换。这些转换要求完整引用或明确的全零值；指针切片后失去引用类型，W 写入的高位零不能恢复原对象身份。合流已有 object 类型时允许其他托管引用向它转换。其他继承关系尚未推导，不能由不同类型直接猜测共同父类。空值临时变量使用已确认类型声明。
- `IntegerProjection` 按实际位宽检查整数表达式，供算术、位运算、比较、选择和返回共用。W 写入后的高位零保留为零扩展；ABI 未定义高位不能用强转补齐。低位截断在寄存器、参数和返回路径共用，引用和浮点值不能直接作为整数使用。
- 整数运算先按整数位宽投影；字段和数组地址只接受已确认类型及布局支持范围内的偏移。大整数常量不能先强转成字段偏移，超出布局范围的指针运算保留为未恢复项。
- `ArrayAddressProjection` 按有类型值追踪数组根、索引和字节偏移，读取、写入及写屏障共用元素定位。索引扩展与缩放可以分属不同指令；只在位宽、索引范围和布局步长均已确认时恢复元素。未绑定的索引地址不能再次当作数组头，已读取的索引保留快照。
- 同宽整数乘法保留低 32/64 位。乘加、乘减和乘积取负组合成公共乘法与加减节点，读取执行前寄存器且不写比较标志；SIMD 同名指令和未定义高位不能套用标量整数投影。
- 标量整数位域提取、插入、清零及符号扩展组合成切片、扩展、掩码和移位。插入读取目标寄存器的旧值；取负共用减法，只有 `negs` 更新标志。任意宽度切片按实际位数生成 C#，跨越已知高位零可以恢复，跨越 ABI 未定义高位仍拒绝；掩码使用截断后的位值。
- `IntegerConditions` 统一 SSA 与回退路径的整数条件表达式，按 32/64 位加、减、按位与生成零、符号、进位与溢出条件。加法判零检查截断后的和，不能替换成两数相等。操作数必须有完整的位宽证据；布尔参数也不能忽略 ABI 未定义高位。布尔字节经清零扩展或低位掩码后可以恢复，入口参数、字节读取及 await 结果合流使用相同边界。
- 引用比较共用 `NativeValues.ReferenceEqual`，空值使用空值模式，完整对象使用 `object.ReferenceEquals`，保留字符串等对象的身份。引用与整数混合、指针截断或未绑定的类型继续拒绝。输出器为常量或调用形式的分支条件补齐括号。

## 当前覆盖

普通 SSA 路径覆盖已绑定字段、部分直接或虚调用、整数或引用返回和无环分支。局部异常区域、尾调用、循环、未确认的栈存储效果等仍走 `FunctionLifter`，保留第七次的恢复能力。两种路径的区别在值传播和源码投影，指令效果已经统一。

机器效果目前覆盖已有样例使用的整数、标量浮点、常见访存和分支指令，不等于完整 ARM64 ISA。SIMD 算术、原子指令和部分 C# 数值投影仍有未支持项。循环投影仅支持已有的有类型标量；堆别名、栈地址逃逸和任意调用副作用仍需进一步证明，统一指令层不会自动解决这些问题。

async 支持现有已验证的 UniTask 协议。通用表达式转换拒绝未支持的位宽变化；不能因为包进 await 就忽略未知值。业务字段快照不包含已证明的状态机捕获与协议字段；复杂业务 Phi、额外状态机存储、任意异常处理和完整 ARM64 指令覆盖仍不支持，不能把当前样例通过解释为一般等价证明。

诊断报告中的 `recoveryPath` 区分 `ssa`、`ssa-async`、`ssa-async-single` 与 `expression`；`OrdinaryProblems` 保留 SSA 路径回退的原因。`.ssa.json` 保存机器值，`.source.semantics.json` 保存最终通用语句树；协议证据另存于 `.async*.json`。

## 回归检查

```powershell
dotnet run --project tests/Cpp2CS.Tests -c Release --no-build -- method-pipeline <配置.json> artifacts/recovered
```

固定使用 `Sekai.Api` 和 `Sekai.Mysekai` 的 15 个入口（含单 await 构造模式），检查正常恢复、同会话逆序、新会话逆序，以及恢复其他方法后再次输出旧结果。C# 文本、语句树和诊断必须一致；14 个无未恢复项，`OnGUI` 保留原有的一个未恢复项。

`SharedBodyChecks` 检查普通与 await 分支合流只输出一次、字段快照不跨调用移动、未知值不被 await 遮蔽。快照定义缺失、晚于使用或只经过一条前驱时必须拒绝；生成的夹具编译执行可检查写入及挂起前后的取值。`async-body-native` 对真实 SSA 做反例变异，破坏挂起分支、token、异常边或将仍被使用的字段读取移入收缩区后必须拒绝归约。

`native-layout <Clang 路径>` 检查匿名聚合的真实大小、独立字段偏移与函数指针别名。全整数聚合的 ABI 可以确定，重叠字段仍保持未知；浮点、混合和未展开的浮点结构体数组继续拒绝。

`python tests/aggregate_abi_oracle.py <配置.json> --tool <测试程序.dll>` 按工具提供的 ABI 给 Clang 编译的 ARM64 函数传参并提取返回值，再通过 Unicorn 执行核对字节校验值与完整返回内容。覆盖 63 组签名，包含 3 组浮点、混合或外层 pack 上下文未确认的重叠布局；其余按 0/6/7/8 个前置整数参数测试寄存器、栈、间接参数和返回缓冲，共 2,400 个场景。参数寄存器的未定义高位填入随机值。分类依据见 [AAPCS64 的聚合与参数传递规则](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst)；此检查不证明字段身份或生成 C# 的行为。

`runtime-types-native <配置.json>` 核对真实方法中 `MethodInfo → klass → rgctx_data` 的类型绑定，以及回退投影是否消费同一 SSA 读取身份；保留尚未恢复的其他业务语义。

`ssa-construction-native <配置.json>` 检查 4,096 条指令的直线图、循环入口与回边、调用正常/异常边，以及真实长方法的 SSA 构造。所有值引用必须闭合，未知入口值不得伪装成参数或调用结果。

`python tests/machine_effects_oracle.py [配置.json] --tool <测试程序.dll>` 默认读取 `native.local.json`，组装 `tests/machine_effects.s`，将机器效果与 Unicorn 逐条对照。覆盖寄存器重叠、W 高位清零、标量浮点高位、移位类别、整数扩展、位域、取负、乘法族、标志、前后索引及成对访存；84 条指令 × 32 组状态，共 5,504 次寄存器、内存与标志比较。不写标志的指令逐一检查标志保持不变。

`python tests/integer_projection_oracle.py <配置.json> --tool <测试程序.dll>` 组装 208 个通用整数函数，经真实解码和源码投影后编译执行。197 个函数与 Unicorn 对照 101,258 组边界和随机输入，另 11 个未定义高位、引用位操作或超范围指针偏移样例必须拒绝。覆盖整数扩展、截断、32/64 位移位及按位运算、乘法与乘加减、不同符号的比较、大整数常量、位域提取与覆盖、取负，以及 W 高位清零后的 64 位运算。包含非字节宽度、符号位边界、寄存器重叠、窄参数及跨字边界切片；模拟执行必须到达返回哨兵。

`python tests/array_projection_oracle.py <配置.json> --tool <测试程序.dll>` 组装 54 个数组函数，45 个生成 C# 与 Unicorn 对照 2,796 组有效数组访问，另 9 个错误步长、未定义高位、32 位缩放回绕、未绑定地址及引用槽位冒充数组的样例必须拒绝。覆盖分步扩展、移位或乘法缩放、先加数据偏移、偏移合并、索引快照及 null 写入；240 次写屏障逐次核对实际数组槽位。原生签名未携带可空标注，编译夹具关闭可空分析；没有验证越界访问或真实 GC。

`python tests/condition_projection_oracle.py <配置.json> --tool <测试程序.dll>` 组装 868 个条件函数；846 个生成 C# 与 ARM64 对照 183,582 组输入，22 个未定义高位、布尔高位、引用混合或截断样例拒绝。两条恢复路径均覆盖 CMP/CMN/TST/ADDS/SUBS 的 14 种条件，以及分支、CSET、CSEL；包含原寄存器被覆盖后仍使用旧标志的情况。恒定标志可产生不可达分支，编译夹具仅允许这类警告，其余错误仍使测试失败。

`python tests/reference_projection_oracle.py <配置.json> --tool <测试程序.dll>` 组装 33 个引用函数，26 个生成 C# 与 ARM64 对照 3,276 组输入，另 7 个类型未确认、引用/整数混合或指针截断样例保持未恢复。覆盖空值合流、object 转换、分支选择、循环交换及空值回边；相同内容的字符串使用不同对象，按引用身份比较。对象和字符串的相等/不等分支同时经过 SSA 与回退路径。`runtime-types-native` 另核对真实字符串元数据槽及字面量/调用返回值的合流。

`arithmetic-native` 保留浮点、数组与成对字段读取回归；`closures-native`、`finally-native`、`call-arguments-native`、`call-storage-native` 分别检查闭包、循环清理、调用实参与调用后的结构体存储。`multi_async_oracle.py --ssa --diagnostics <目录>` 对真实方法做逐指令 SSA 对照，再由 `compile_multi_async.py <目录>` 编译并执行同批生成的 C#；诊断目录默认均为 `artifacts/recovered`。

`python tests/call_memory_oracle.py <配置.json> --tool <测试程序.dll>` 对照调用后的栈读取、已保存的寄存器值和返回缓冲。外部调用的顺序、实参和返回值均与 ARM64 执行比较；指针写入、后续逃逸使用、单分支逃逸和返回缓冲之外的未知写入必须报告缺口。真实构造器未满足纯字段写入证明时，`call-storage-native` 检查后续调用不再沿用旧栈常量。

生成代码的测试桩编译执行与 ARM64 模拟执行仅覆盖各自的输入和外部调用契约，不代表真实游戏或 UniTask 调度器已验证。
