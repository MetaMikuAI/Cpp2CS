# 汇合类型恢复验证

## 实现与边界

`ValueRecovery` 原先要求 φ 的所有来源先具有类型，并以寄存器完整宽度读取。这会阻塞循环中的相互依赖，也会拒绝部分合法的窄值。

- 从常量、运算和比较取得结果类型约束，再传播到定义和 φ。
- 展开 φ 之间的环，由环外来源确定类型；没有外部来源的环保持未知。
- 数值来源保留位型，允许合并符号不同的整数；引用可合并到共同基类，已证明为零的来源可作为空引用。
- 推断结束后检查每个定义和每条输入边。未知操作数、不兼容类型或缺失来源会撤销结果，并继续撤销依赖它的类型。
- 只有 IR 明确清零高位的窄定义，及全部来源均满足这一条件的 φ，才允许补零后宽读。入口参数和调用返回的未定义高位仍不能读取。
- 字段读取仍留在原定义处；循环边继续使用先读全部来源、再写目标的同时赋值。

类型约束不是方法恢复证明。栈对象、异常区域、聚合值和间接调用仍有缺口，很多循环仍无法完整输出。此阶段尚未接入按分支条件确定的零值；后续[条件边恢复验证](条件边恢复验证.md)已处理 `MysekaiGateModel.InitializeBasicProperties`（`0x58a40a4`）的判空汇合，不将任意对象地址转成数值。

## 执行验证

`phi-check` 从合成机器 SSA 经完整方法恢复生成 CIL，实际执行整数分支、宽窄合并、循环累加与溢出、互相交换的 φ 环、浮点 NaN/负零、空引用和公共基类合并。反例检查未知回边的撤销、无来源环、不兼容引用，以及入口参数和调用返回的高位。

新增的真实样本：

| 方法 | 地址 | 已验证行为 |
| --- | --- | --- |
| `FixtureController.GetColors` | `0x5843760` | 读取 model 和颜色集合；集合为空时返回 null，否则返回原数组 |
| `FixtureModel.get_FixtureColorDataCollection` | `0x585c820` | 上述调用者的真实 getter 依赖 |
| `HarvestPlayerModel.get_TargetHarvestUid` | `0x58dc720` | 读取目标采集对象；目标为空时返回 null，否则返回原 UID 引用 |
| `HarvestBaseView.get_UniqueId` | `0x58becf0` | 上述调用者的真实 getter 依赖 |

四个方法体均由真实二进制恢复，测试未提供手写 getter 实现。替代宿主只提供字段和引用身份；检查空分支、空字段、原引用/数组身份、切换字段后的重复调用，以及必要宿主为空时的空引用异常。循环执行测试仍为合成样本，不能当作真实循环业务已验收。未加载 Unity 游戏运行时。

原有 `body-check` 和 `accessor-check` 执行测试继续通过。

新旧 case 集合完全一致。新增输出为 `SetIKTargetNpc`、`GetColors`、`get_TargetHarvestUid`、`DecreaseHarvestObjectHp`，以及两个 `SortCellDataList` 的编译器生成方法。其中只有上表列出的两个新增调用者完成本轮真实方法执行检查；其余输出不能据此算作行为通过。

