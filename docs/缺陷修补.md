# 缺陷修补

恢复层由模型组成，缺陷按它违反的是哪一层的事实来修补，而不是为出错的形态加条件。本文给出定位方法、各层的修补面和验收方式。

## 定位

1. 用执行对照找出 mismatch，用 `recovery.jsonl` 找出洞；以执行对照为准，写出数量不说明正确。`cpp2cs holes <输出目录>` 按原因汇总受影响方法数，并列出有洞方法的拒绝规则与未归一的运行时痕迹，先补影响面大的原因。
2. 用 `cpp2cs inspect <入口> --fact-cache-file …` 逐层查看：机器 IR、局部内存单元、符号值、下降后的方法体。
3. 找到第一层与预期不符的产物。缺陷属于这一层，不在下游补偿。

| 第一处不符 | 所属层 | 修补面 |
|---|---|---|
| 调用目标、签名、栈实参的位置 | 事实与 ABI | `ManagedAbi.Machine`、`CallShapes`、`MethodEntries` |
| codegen 的固定序列没有归一为运行时操作 | L2 | `Idioms` 中的识别 |
| 运行时操作的语义（结果类型、内存效果、下降） | 注册表 | `RuntimeOps` 的一项 |
| 机器值的位来源 | 符号值 | `SymTable` 的规范化 |
| 栈槽的来源、地址是否逃逸 | 帧内存 | `FrameModel`、`CallMemoryEffects` |
| 局部内存的单元、调用效果 | 内存 | `MemoryPromotion` |
| 完全共享泛型的句柄与位置 | L2 | `SharedValuesPass` |
| 初始化守卫两臂的等价 | L2 | `OnceGuardsPass` |
| 合流后需要单一实体 | 拆分 | `PathSplitting` 的判据 |
| 地址对应的位置、原子的类型 | 类型 | `TypeOracle` |
| 检查吸收、非空事实、初始化与异常顺序 | 效果 | `EffectAnalysis` |
| 同宽计数器的初值、步长与回边关系 | 机器控制流 | `InductionVariables` |
| 值类型构造的覆盖证据与形参绑定 | 模板证明 | `TemplateRecovery.ValueConstructions` |
| 位置、值或语句的托管表达 | 下降 | `BodyBuilder` 各分部 |

## 修补的形式

每次修补应能用下面一种形式陈述；陈述不出来的，说明对缺陷的理解还不够，先不改代码。

- **补事实**：元数据、布局、ABI、注册表中本来存在但没有读出的信息。依据是 IL2CPP 的生成约定或运行时结构。
- **补定义**：模型对某种操作没有定义，例如一种机器运算的位搬运、一种运行时操作的内存效果。定义对所有输入成立，不检查调用点的形态。
- **补等价**：两种表示在语义上相同，但模型只认其中一种。例如结构体值按叶子组成等于整个字段，单次赋值的局部等于它的值。以语义证明为依据。
- **补逆变换**：编译器的一种优化尚无对应的逆，例如内联、合并、提升。逆变换以可检验的证据成立，例如被调方法自身的恢复体，并在证据不足时报洞。

以下做法不属于修补：

- 按方法名、类型名、地址或样本中的具体常量分支；
- 为让某个样本通过而放宽判定、跳过检查或补默认值；
- 在下游掩盖上游的错误，例如在下降中特判某种符号值的形状，而它本应在规范化中得到。

缺省解释（如不受约束的值按同宽整数）只能出现在模型明确定义的位置，并在文档中写明依据。

下降是机械的：`BodyBuilder` 不以语句对象为键保存跨语句的状态，不创建符号值，也不扫描语句序列识别形态。需要这些时，事实属于上游的某个模型（多次访问构成一次访问属于 `TypeOracle.Accesses`，两种类型共用位型属于 `TypeOracle.Representation`），在那里定义后由下降查询。同一概念只在一处判定；第二处需要同一判断时，把判断上移为模型的查询。

## 证据与报洞

不能证明的情形记为洞，原因写明缺少的事实或失败的证明步骤，例如"构造函数体不只是转给基类构造"。洞是待补模型的清单，不用占位实现冒充恢复成功。修补后原来的洞消失，执行对照不出现新的 mismatch。

## 验收

1. 构建通过。
2. 两个本地样本的 `recover` 与 `execute`：verified 不减少，不出现新的 mismatch；写出数量下降时逐个说明原因（通常是此前写出了错误代码，现在如实报洞）。
3. 提交说明写明修补属于上面哪种形式、依据是什么。
4. 修补引入新的扩展点或改变层的职责时，同步更新 `docs/架构.md`。

## 尚未建模的部分

下表是当前已知、需要单独建模的部分。它们各自属于某一层，按上面的方式推进，不以规则堆叠代替。

| 部分 | 所属层 | 现状与方向 |
|---|---|---|
| 多语句方法的内联：调用点特化 | 逆变换 | 模板的分支在绑定之下求值，并携带调用方路径上的条件与判空事实（`KnownCondition`）；能判定时模板只走一侧。仍失败的情形按洞的说明（"内联证明：…"）统计后再扩展 |
| 多语句方法的内联：跳转线程化 | 逆变换 | 续接点观察到的值与谓词都是返回值的函数（`TemplateRecovery.Exits`）；返回之后的代码被复制到各路径时，两边同步走，等价就是同一个续接（`TemplateRecovery.Duplicates`） |
| 完全共享泛型的执行对照 | 验证 | 独立 AAPCS64 分类器不描述不透明值，这类方法记为不可检查，语义未经对照 |
| 泛型定义只有一个见证 | 输出 | 定义按一个原生实例写出；值类型实例被折叠掉的分支不会出现在定义里。透明执行时按被内联实例自己的恢复体，写出的定义体本身仍是见证实例的语义 |
| 精确初始化的类型 | 验证 | 对照器按 CLI 规则在静态调用前记 cctor 事件，IL2CPP 不访问静态字段的方法不运行它，这类方法的 mismatch 不是恢复错误，尚未建模 |
| 多语句方法的内联：纯取值方法 | 逆变换 | 返回值被丢弃、或由分段读取直接组成返回表达式的情形已接入。尚未覆盖：无副作用的取值方法被内联后结果直接用在其他表达式里。方向：无副作用的模板作为表达式代入使用处 |
| 平台调用包装 | L2 与注册表 | 运行时的导入解析、参数封送是固定序列，归一为运行时操作后由注册表给出语义 |
| 元数据实体上的其他读取 | 符号值 | 目前只解析类的虚表槽；元素类、RGCTX 等按运行时布局扩展 `MetadataRead` |
| 相邻读取合并为结构体读取 | 下降 | 可读性改进，不影响语义 |
| finally、取模等源码形态的整理 | 源码整理 | 在写出之后进行，不进入恢复层 |
