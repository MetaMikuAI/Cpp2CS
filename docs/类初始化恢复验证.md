# 类初始化恢复验证

## 恢复规则

类初始化可能执行静态构造函数并抛出异常，不能当作无副作用的运行时准备删除。恢复后在原调用位置输出 `RuntimeHelpers.RunClassConstructor(typeof(T).TypeHandle)`；类型无法确定时报告缺口。

- 从匹配元数据的 `TypeInfo` 确定类型，保留泛型实参。类型句柄使用 CIL 的 `ldtoken`。
- 当前仅核对元数据版本 31、ARM64 的类布局：`static_fields` 为 `+0xb8`，`cctor_finished` 为 `+0xe0`。其他布局不借用这些偏移。
- 完成标志的快速分支仅在同一类型、完整 32 位判零、单一初始化路径且没有额外副作用时消除。初始化调用保留，由 CLR 负责重复调用和失败缓存。
- 返回类型指针的包装函数必须逐项核对实际调用参数、完成标志、分支方向、返回值和额外读写。当前接受直接初始化或单个快速分支，不因“返回原参数”就认定它只是初始化。
- 仅在所有路径都返回原参数时，包装结果才继续作为元数据指针传播，不能冒充普通 CLR 对象。真实包装 `0x44106e8` 的慢路径尾调用无返回值的初始化函数，快速路径返回原指针不足以证明整体返回值。

## 执行检查

合成检查同时执行恢复 CIL 和重新编译后的 C#：初始化位于两个可见副作用之间；成功时只执行一次；失败时保留异常、缓存失败结果且不执行后续语句。反例覆盖错误类型、错误偏移、窄位比较、倒置分支、额外读写和回边。

| 真实方法 | 地址 | 检查 |
| --- | --- | --- |
| `PathUtility.GetFileCombinePath` | `0x55d2b5c` | 串联下方恢复方法，CIL 与 C# 重新编译执行 |
| `PathUtility.GetSlashCombinePath` | `0x55d2ac4` | 保留 `System.IO.Path` 初始化，覆盖空输入、多段路径、反斜杠、中文和空引用 |
| `ScreenLayerMysekaiCanvas.get_ContentListTypes` | `0x5acb814` | CIL 与 C# 重新编译执行，枚举数组内容及多次分配独立 |
| `GetSuiteUserPartsApi..ctor(long)` | `0x51f7578` | CIL 保留具体泛型基类的初始化，基类调用和字段写入执行 |
| `IdleLowerState..ctor`，三参数与四参数 | `0x5631084` / `0x56310e4` | 既有构造委托的 CIL 与 C# 往返、参数位型和异常顺序回归 |

路径库使用当前 CLR，构造检查使用记录宿主；真实恢复的方法体没有被手写实现替代。以上不证明 Android 路径库的平台差异、API 请求或 Unity 游戏运行行为。

## 全量与源码边界

输入二进制和元数据哈希同[值布局验证](值布局验证.md)，范围仍为 `Sekai.Mysekai`、`Sekai.Api` 及全部子命名空间。

| 项目 | 数量 |
| --- | ---: |
| 全部代码 case | 23,390 |
| 可形成托管方法体 | 9,329 |
| 写出 CIL 的目标 case | 9,050 |
| 相比构造恢复基线新增 / 回退的 CIL case | 0 / 0 |
| 含显式类初始化的已输出 case | 498 |
| 这些 case 中的类初始化调用 | 524 |
| 回读通过的方法定义，含恢复依赖 | 9,187 |

目标 case 的地址与方法定义对应不变。此次补回执行语义，没有增加已输出 case 数。相对 `recovered-constructor-storage`，288 个源码文件变化：主程序集 287 个、Grid.Data.ValueObject 1 个；其他程序集源码不变。

主程序集 1,701 个目标文件的 C# 诊断由 7 项增至 156 项，涉及 149 个文件。其中 152 项为构造调用无法表达为合法 C#，另 4 项为缺少基类构造参数；范围外仍有 2 项既有错误。Grid.Data.ValueObject 的全部 19 个文件、其中 10 个目标文件为零错误。

原因是部分原生构造函数在基类实例构造前显式初始化类型。恢复 CIL 能保留这个顺序，当前 C# 输出器却不能直接表示，会留下 `base._002Ector(...)`。不得将初始化移到基类构造之后来消除诊断；保序的 C# 表达仍待实现。CIL 输出数也不代表依赖完整或业务可运行。

最终证据目录为 `artifacts/recovered-class-init-final/`；构建、专项检查和全量日志为 `class-init-final-build.log`、`class-init-final-check.log`、`class-init-final-bodies.log`。尾调用返回值修正后，1,747 个源码文件与已检查的 `recovered-class-init-proof` 逐字节一致，比较记录为 `class-init-final-comparison.json`。

路径与构造执行日志为 `class-init-proof-runtime.log`、`class-init-proof-constructors.log`；源码诊断日志为 `compile-class-init-proof.log`、`compile-class-init-proof-grid.log`。构建零错误，第三方 NSO 读取仍有三项既有警告。生成物不提交 Git。
