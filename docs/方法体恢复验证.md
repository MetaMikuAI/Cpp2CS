# 方法体恢复验证

目标仍为 `Sekai.Mysekai` 和 `Sekai.Api`（含子命名空间）的全部代码 case。当前输出不代表全量恢复完成，未恢复成员和依赖程序集仍有骨架方法。

## 实现

- `ValueRecovery` 从签名、字段布局、唯一托管调用传播类型。字段读取留在原定义处，后续引用局部值，避免跨写入重新读取。
- `BodyRecovery` 恢复字段写入、调用、返回和控制流；φ 按前驱转为边上的同时赋值。任何未恢复语句、CFG 问题或异常区域都会阻止输出该方法。
- `BodyEmitter` 将托管方法体写为 CIL，再由现有反编译器输出 C#。先检查支持范围，失败时不替换原方法体。
- 整数保留机器位宽、符号和截断规则；浮点位重解释不做数值转换。分支边先读取全部源值，再写目标，保留循环中的交换语义。
- 未确认基类初始化的引用类型构造函数不输出裸 `ret`。具体泛型实例尚不写回开放方法定义。
- 字段和调用必须满足托管访问权限。原生内联留下的跨类私有字段访问，仅在访问器等价证明后改为调用，见[内联访问器验证](内联访问器验证.md)。
- 恢复中的源码保留显式字段和访问器，关闭自动属性、`field` 关键字和结构体字段初始化变换，避免在方法体与骨架混合时丢失字段声明或错误移动赋值。
- 整数除法异常边界、浮点转整数的饱和、聚合返回、栈对象、异常处理等仍有缺口；不以 CLR 中看似相同的运算替代尚未确认的机器语义。

## 检查命令

在 `Cpp2CS/` 中运行：

```powershell
dotnet build tests/Cpp2CS.Tests/Cpp2CS.Tests.csproj --no-restore -m:1 -p:UseSharedCompilation=false -o artifacts/body-tools -v:quiet
dotnet artifacts/body-tools/Cpp2CS.Tests.dll value-check ../lib/arm64/libil2cpp.so ../lib/arm64/global-metadata.dat
dotnet artifacts/body-tools/Cpp2CS.Tests.dll body-check ../lib/arm64/libil2cpp.so ../lib/arm64/global-metadata.dat
dotnet artifacts/body-tools/Cpp2CS.Tests.dll bodies ../lib/arm64/libil2cpp.so ../lib/arm64/global-metadata.dat artifacts/recovered-bodies Sekai.Mysekai,Sekai.Api
dotnet artifacts/body-tools/Cpp2CS.Tests.dll compile-saved artifacts/recovered-bodies/assemblies Sekai.Mysekai,Sekai.Api Assembly-CSharp
```

`bodies` 对每个 case 记录恢复结果、失败原因与输出状态。没有全部恢复时返回 1，输出仍保留；未捕获的异常表示工具检查失败，不能与正常的未完成状态混淆。

输出位于指定目录：

- `manifest.jsonl`：逐 case 的结果。只有 `cilEmitted=true` 的方法替换了骨架。
- `missing-methods.jsonl`：有非抽象定义但没有代码的条目；不能从失败统计中遗漏。
- `summary.json`：二进制哈希、覆盖数、回读数与源码文件数。
- `assemblies/`：带已恢复方法的程序集，其他方法仍是骨架。
- `src/`：目标命名空间的 C#，同样包含未恢复成员，须结合清单阅读。

## 证据边界

`body-check` 实际加载并执行生成的 CIL，覆盖整数边界、窄值溢出、移位、浮点位型与 NaN、循环边赋值、字段读取顺序和直接调用。大部分是合成测试，不能当作真实业务方法成功。

真实 case 选取 `Sekai.Mysekai.DebugCharacterSpawnEventData`：

| 地址 | 方法 | 二进制行为 |
| --- | --- | --- |
| `0x55d261c` | `get_CharacterId` | `ldr w0,[x0,#0x14]; ret` |
| `0x55d2624` | `set_CharacterId` | `str w1,[x0,#0x14]; ret` |

检查使用真实二进制、元数据和恢复管线，只把宿主类型替换为测试类，执行生成的 getter/setter 并核对整数边界输入。这不包含 Unity 游戏运行时，也不证明其他 case 的行为。

二进制和元数据 SHA256 见[值布局验证](值布局验证.md)。
