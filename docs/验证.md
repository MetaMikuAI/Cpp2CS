# 验证

## 通用检查

```bash
dotnet build Cpp2CS.slnx -c Release
dotnet run --project tests/Cpp2CS.Tests -c Release -- unit-tests
```

无参数运行测试程序可查看命令及参数。检查由 `[Command]` 声明；`unit-tests` 运行不依赖目标映像的检查，失败返回非零。测试构造的 IR、CIL 与数值边界不包含具体程序样本。

## 输入与产物检查

```bash
dotnet run --project tests/Cpp2CS.Tests -c Release -- facts <binary> <metadata>
dotnet run --project tests/Cpp2CS.Tests -c Release -- compile <output>
dotnet run --project tests/Cpp2CS.Tests -c Release -- ilverify <output>
dotnet run --project tests/Cpp2CS.Tests -c Release -- execute <binary> <metadata> <output>
```

原生执行使用 Unicorn，需要安装并配置可加载的本机库，可用 `UNICORN_LIB` 指定库路径。
零链接基址的 ELF 头可能映射在地址零；执行对照单独截获空指针页读写并记为不可检查，避免错误地读写映像头。`native-null-page` 用独立 ARM64 指令核对这一边界。
`execute --only <methods.tsv>` 限定对照范围；`--mutants` 评估比较器对注入错误的检出情况，不代表恢复覆盖率。

`cil-delta <before> <after> <report>` 比较完整写出方法的 CIL，`--source` 比较源码整理后的版本。`--partial` 单独比较含缺口标记的部分方法体，并核对报告中的部分写出数量；这部分不计入完整恢复指标。

重构使用同一方法清单和同一 profile 对比。`architecture <仓库目录>` 检查模块依赖；`recovery-delta <before> <after>` 比较逐方法状态、洞与 C# 文件；`artifact-consistency <output>` 核对发布记录、磁盘 CIL 和运行清单中的产物摘要。新增计时、步骤追踪和洞类别不参与旧产物的零差异判断。

`source-files-compile <output>` 将 `src/` 中实际导出的 C# 文件一起编译，诊断写入 `source-compile/compile.txt`；失败返回非零。只导出部分类型时，与依赖 DLL 同名类型的身份冲突也会报错，须与恢复代码自身的错误分别分析。

`type-scope-inventory` 建立指定类型及嵌套类型的清单，包含已登记的泛型共享入口，并单独保存全部原生实例的固定字节分母。`type-source-view` 可用新输出规则重新导出同一批程序集，不重复原生恢复。

`source-quality <inventory> <output> <report>` 按目标源码统计转义标识符、后备字段、未恢复调用、显式 `MoveNext` 声明和 `throw null`，同时报告完整方法数及原生字节覆盖率。字节分子只计完整写出的目标入口并去重；源码折叠不增加覆盖率。`source-scope-compile` 另存该范围的编译诊断，报告命令返回成功不代表源码零错误。

这两项范围检查支持平铺和项目目录；项目文件合并泛型同名类型时，编译引用范围由实际源码声明确定。比较前后须使用同一清单、同一验证工具与相同引用策略。

架构回归还需比较 `--jobs 1` 与多线程的规范 CIL、逐方法状态和源码内容，排除时间、运行 ID 等非确定字段。`facts-cache <binary> <metadata> <report> cold` 与 `warm` 分进程比较完整事实、ABI、检查记录和实际方法样本，不以“命中缓存”代替内容一致。

失败路径应从已有产物挑选少量真实方法，对照独立缺口、派生关系和部分输出；完整恢复样本无法覆盖错误传播。`analysis-snapshot`、`recovery-result`、`native-binding` 分别检查失效边界、显式失败和多入口布局隔离。

`runtime-delegate` 检查真实 CLR 泛型委托的运行时标志、ref 参数签名和拒绝边界。运行时声明数及其关联原生字节单列，不等于方法体恢复或原生执行对照通过。

`platform-import <binary> <metadata> <入口地址…>` 检查真实导入包装及其参数、缓存、副作用变体；它核验导入声明，不代表外部动态库已在目标平台运行。

泛型执行对照先核对磁盘中的开放泛型 CIL，再用注册表实例代入类型参数，与清单中的原生入口比较。通过一个引用共享实例不代表同一定义的值类型实例或其他原生入口也已验证。
变异测试使用相同的实例及原生入口。`--only` 使用写出清单中的入口和开放方法名，存在未匹配项时立即报错，防止零方法检查被误记为通过。

`execute --concrete-generics` 为引用共享入口选择二进制元数据槽中实际使用、且能提供更多非空接口输入的具体实例。候选必须映射到同一个原生入口；日志记录实例与槽位。它只改变对照输入，不改变恢复体或比较规则。

`tests/oracle/` 提供 ARM64 指令和编译器模式的独立对照脚本。`tests/execute_sharded.py` 接收显式输入路径，对写出方法分片执行；`tests/report.py` 汇总产物及差异。具体样本和基线由使用者在本地提供。

## 判定

| 检查 | 能说明的内容 |
|---|---|
| 基础事实检查 | 注册表、布局和代码地图满足实现中的约束 |
| 编译、ILVerify | 产物通过对应工具的静态检查 |
| 原生/CIL 对照 | 已覆盖输入在合成运行时中的行为是否一致 |
| 源码对照 | 整理后的源码在指定测试条件下的行为 |
| 实际运行 | 产物在真实运行环境中的表现，需要独立验证 |

`verified`、`mismatch`、`not-checkable` 分别表示已覆盖输入通过、不一致、对照器无法检查。未覆盖路径和未建模服务仍是验证边界。全量与抽样、完整与部分方法、目标与依赖方法应分别统计；不能把未检查或不可检查计为通过。
