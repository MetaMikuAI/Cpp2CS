# 验证

## 通用检查

```bash
dotnet build Cpp2CS.slnx -c Release
dotnet run --project tests/Cpp2CS.Tests -c Release -- unit-tests
```

无参数运行测试程序可查看命令及参数。检查由 `[Command]` 声明；`unit-tests` 运行不依赖目标映像的检查，失败返回非零。测试构造的 IR、CIL 与数值边界不包含具体程序样本。

## 输入与产物检查

```bash
dotnet run --project tests/Cpp2CS.Tests -c Release -- facts <binary> <metadata>
dotnet run --project tests/Cpp2CS.Tests -c Release -- compile <output>
dotnet run --project tests/Cpp2CS.Tests -c Release -- ilverify <output>
dotnet run --project tests/Cpp2CS.Tests -c Release -- execute <binary> <metadata> <output>
```

原生执行使用 Unicorn，需要安装并配置可加载的本机库，可用 `UNICORN_LIB` 指定库路径。
`execute --only <methods.tsv>` 限定对照范围；`--mutants` 评估比较器对注入错误的检出情况，不代表恢复覆盖率。

`cil-delta <before> <after> <report>` 比较完整写出方法的 CIL，`--source` 比较源码整理后的版本。该检查不覆盖所有部分方法体。

泛型执行对照先核对磁盘中的开放泛型 CIL，再用注册表实例代入类型参数，与清单中的原生入口比较。通过一个引用共享实例不代表同一定义的值类型实例或其他原生入口也已验证。

`execute --concrete-generics` 为引用共享入口选择二进制元数据槽中实际使用、且能提供更多非空接口输入的具体实例。候选必须映射到同一个原生入口；日志记录实例与槽位。它只改变对照输入，不改变恢复体或比较规则。

`tests/oracle/` 提供 ARM64 指令和编译器模式的独立对照脚本。`tests/execute_sharded.py` 接收显式输入路径，对写出方法分片执行；`tests/report.py` 汇总产物及差异。具体样本和基线由使用者在本地提供。

## 判定

| 检查 | 能说明的内容 |
|---|---|
| 基础事实检查 | 注册表、布局和代码地图满足实现中的约束 |
| 编译、ILVerify | 产物通过对应工具的静态检查 |
| 原生/CIL 对照 | 已覆盖输入在合成运行时中的行为是否一致 |
| 源码对照 | 整理后的源码在指定测试条件下的行为 |
| 实际运行 | 产物在真实运行环境中的表现，需要独立验证 |

`verified`、`mismatch`、`not-checkable` 分别表示已覆盖输入通过、不一致、对照器无法检查。未覆盖路径和未建模服务仍是验证边界。全量与抽样、完整与部分方法、目标与依赖方法应分别统计；不能把未检查或不可检查计为通过。
