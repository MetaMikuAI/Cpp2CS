# 控制流清理验证

## 规则

- 常量传播、删除不可达块和条件边清理交替执行，直到没有可删除的边。运行时纯调用删除、栈槽提升之后也重新清理。
- 常量条件保留对应侧；两侧到同一目标时，只有对应的 φ 输入相同才能合并。经空块汇合的路径也要求 φ 输入相同。
- 删除边与恢复托管边赋值均按后继位置对应前驱位置。同目标的跳转边、顺序边和异常边分别保留自己的 φ 输入。
- 条件中的内存读取、未知 intrinsic、侧路径调用及异常落地块不会作为无效果分支删除。分配、初始化及其他调用位置不变。

## 验证

`control-flow-check` 对 510 组输入比较变换前后的机器 IR 执行结果，覆盖常量、连续传播、循环、重边和不同 φ 来源；另检查条件读取、侧路径调用、异常边及栈槽提升，并核验 SSA。

重边样本经过完整托管恢复、CIL 输出、C# 重编译与执行，验证同目标两侧仍分别选择正确的 64 位输入。既有条件边检查的 1,108 组输入通过。

真实方法 `MysekaiGateModel.InitializeBasicProperties`（`0x58a40a4`）执行检查通过，覆盖空数据、布尔双分支、旧字段覆盖、重复调用和空 `this`。既有内联构造 CIL/C# 执行检查通过。

`MaterialRenderingSettings..ctor`（`0xa45d4c8`）中，运行时类型检查删除后形成的空分支已消除，分配、构造和数组写入顺序保持。外层构造尚未运行：`PassRenderingSettings..ctor` 仍因相邻字段的合并写入未恢复而保留骨架。执行检查使用替代宿主，没有验证 Unity 运行时。
