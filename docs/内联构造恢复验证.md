# 内联构造恢复验证

## 恢复规则

- 从分配对象的元数据查找实例构造函数，重新分析真实地址并恢复完整方法体。只有方法边界、签名和直接基类初始化均可确认时，才建立构造证明。
- 对比分配之后的整个内联片段，包括字段值、读取、调用、局部值关系和顺序。构造前的字段写入不会被移到基类调用之后；中间多出操作或缺少后半段均不匹配。
- 构造参数只能来自原 SSA 中已求值的片段外输入、局部或常量。不会把后面的字段读取提前为参数，不猜测已经被优化掉的未使用参数。
- 被取地址的参数存储、构造私有栈位置、私有临时值在片段之外仍被使用等情况，暂不提取为调用。
- 匹配后保留原分配位置，以实际构造调用替换片段。输出时先验证全部构造依赖，再同时写出真实实现与调用者。
- 相邻调用继续沿用[对象分配恢复](对象分配恢复验证.md)的合并规则。本类静态构造函数内创建本类对象也可以合并：同一线程已处于本类初始化中，不会再次进入静态构造。其他静态初始化关系不据此类推。

当前证明支持非泛型、无分支和回边的完整构造体；调用者中的匹配片段位于同一基本块。泛型构造证明、跨块片段及带分支构造仍需继续恢复。统一的托管值遍历用于临时存储检查和 `this` 初始化检查，未识别的值种类直接暴露错误。

## 执行证据

合成检查生成实际构造依赖和工厂方法，执行 CIL 及 ILSpy 输出的 C# 重编译结果：

- 只读默认字段先写为 `2000`，基类构造观察到该值，随后保存传入的对象引用。
- 基类传出的对象和工厂返回的对象身份一致。
- 基类抛异常时，已写默认字段和逃逸对象保留，后面的引用赋值没有执行。
- 字段值、顺序或片段长度不符，额外副作用，晚发生的字段读取，被取地址的局部，向外泄漏的临时值和缺失参数均拒绝匹配。
