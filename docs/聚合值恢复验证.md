# 聚合值恢复验证

## 恢复范围

此前 ABI 已能描述多个寄存器中的结构体，但托管恢复只接受单分量。现在连接参数入口、调用参数、调用返回和方法返回四个位置。

- `AggregateValues` 根据具体字段布局拆分和组装值类型，支持同质浮点聚合、整数寄存器中的多个数值字段，以及完整引用字段。
- 数值使用位移、截断和位重解释，保留浮点负零、无穷和 NaN 位型；不会把数值转换成指针或对象引用。
- 多分量调用返回先存入一个完整的局部值，再读取各分量，调用只执行一次。新局部变量避开已有机器临时变量。
- 输出通过字段组装结构体，不调用未经验证的构造函数。已证明所有字段来自零分量时输出 `default`，可用于只读结构体。
- 类型赋值检查不再把值类型的元数据基类当作隐式引用转换；装箱需要单独恢复。

缺失分量、重叠字段、未知布局、填充字节读取、拆碎的引用和非零只读字段初始化仍会报告缺口。大结构体的间接参数、x8 返回缓冲区、栈参数、异常处理和开放泛型方法体尚未补齐。以上能力不代表任意结构体已经可以恢复。

## 真实方法执行

输入二进制与元数据哈希同[值布局验证](值布局验证.md)。

| 方法 | 地址 | 检查 |
| --- | --- | --- |
| `StaminaData.get_Zero` | `0x58f557c` | 三个字段均为零 |
| `StaminaData.op_Addition` | `0x58f5588` | 25 组输入，逐字段加法和溢出 |
| `StaminaData.op_Subtraction` | `0x59015f0` | 25 组输入，逐字段减法和溢出 |

元数据确认 `normal`、`enhance`、`boost` 为偏移 0、4、8 的三个 `Int32` 字段。原生代码用 x0 的两个半部和 w1 返回结果；二元运算的第二个参数使用 x2、w3。恢复保留原生打包运算，没有为这些方法编写专用归约规则。

测试从真实二进制恢复方法体，写出 CIL，并在按元数据构造的替代类型中执行。替代类型只提供字段布局，不提供手写方法实现，也没有替代业务调用。覆盖 `int.MinValue`、-1、0、1、`int.MaxValue` 的组合。没有加载 Unity 游戏运行时，不能据此声称游戏内验证通过。

另外，合成 SSA 与执行测试覆盖：浮点聚合往返、多寄存器调用参数与返回、打包整数、双精度位型、引用身份、返回调用次数、新旧临时变量冲突、嵌套字段和无效布局拒绝。这些检查是通用规则测试，不是真实游戏方法的执行证明。

## 全量结果

测试范围为 `Sekai.Mysekai`、`Sekai.Api` 及其子命名空间，包含全部代码实例。

| 项目 | 数量 |
| --- | ---: |
| 代码 case | 23,390 |
| 可形成托管方法体 | 8,455 |
| 写出 CIL 的目标 case | 8,118 |
| 相比 `27d21a8` 新增 / 回退 | 98 / 0 |
| 尚未写出 CIL | 15,272 |
| 回读通过的方法定义，含访问器依赖 | 8,229 |

前后 case 集合完全一致。1,747 个目标源码文件中有 56 个变化：`Assembly-CSharp` 54 个，`Sekai.Mysekai.HUD.Grid.Data.ValueObject` 2 个。这两个程序集重新检查后，1,701 和 10 个目标文件均为零编译诊断错误；主程序集仍有既有的两项范围外错误。其他三个程序集的 36 个目标文件逐字节未变，沿用此前检查。

`body-check`、`phi-check`、`stack-check` 原有执行检查通过。全量 CIL 回读和 C# 编译诊断不等于其余新增方法已经逐一通过行为验证；未恢复成员仍是骨架。

证据在 `artifacts/recovered-aggregate-final/`、`aggregate-verified-check.log`、`aggregate-final-bodies.log`、`aggregate-body-check.log`、`aggregate-phi-check.log`、`aggregate-stack-check.log`、`compile-aggregate-main.log`、`compile-aggregate-grid.log`。日志均在 `artifacts/` 下，不提交生成物。

## 前置栈对象能力

`27d21a8` 已加入从引用参数签名确定栈对象、共享整体与字段引用、按控制流检查读取前初始化的能力。未知地址用途、类型冲突和未初始化读取会阻止输出。

真实 `UIPartsMysekaiRankGauge.OnRankUp`（`0x570a9a4`）执行检查覆盖整数边界、UI 实参和空接收者。整数转换使用 CLR 实现，UI 是记录参数的测试依赖；这只证明恢复后的调用者，不能代替原始 UI 或游戏验证。
