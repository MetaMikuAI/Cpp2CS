# 实施

[设计](设计.md) 定下目标、哲学和各层的契约。本文是工程上的落法：工程结构、核心概念怎样建模、一个事实该放在哪、任务怎样做、起步的工作包。两者冲突时以设计为准。

本文的代码片段都是示意，名称与签名可以调整；表格里“放在哪”一列是约束。

## 1. 工程结构

### 1.1 解决方案

.NET 10，C# 最新语言版本，开启可空引用，警告视为错误，包版本集中管理。这些设置沿用上一轮的 `Directory.Build.props`、`Directory.Packages.props`、`NuGet.Config`。

```
Cpp2CS.slnx
src/
  Cpp2CS.Model/            元数据模型、类型、布局
  Cpp2CS.Native/           原生 IR、目标接口、映像的中立抽象
  Cpp2CS.Targets.Elf/      文件格式：ELF
  Cpp2CS.Targets.Pe/       文件格式：PE
  Cpp2CS.Targets.Arm64/    指令集：ARM64；AAPCS64
  Cpp2CS.Targets.X64/      指令集：x86_64；SysV，之后 Win64
  Cpp2CS.Runtime/          运行时规格的读取、运行时函数目录、运行时操作登记表
  Cpp2CS.Kernel/           项、程序快照、状态模型、事件、路径事实、查询、等价引擎
  Cpp2CS.Recovery/         运行时命名、定位与类型、结构还原、下降
  Cpp2CS.Managed/          托管方法体
  Cpp2CS.Input/            元数据适配、全局事实的构建与缓存
  Cpp2CS.Output/           CIL、表示层、C# 导出
  Cpp2CS.Pipeline/         装配、阶段、报告
  Cpp2CS.Cli/

corpus/                    语料：C# 用例、构建脚本、真值抽取脚本
tests/Cpp2CS.Tests/        性质检查、契约检查、执行对照
third_party/Il2CppDumper/  子模块
docs/
```

- 异常模型、OS 约定可以并在对应的格式或指令集项目里，也可以单列，由实现决定。
- `spec/` 里放生成出来的布局与目录数据，以及 `spec/gen/` 下的生成器与核对脚本；不放运行时的头文件。
- `corpus/` 里只放用例源码与脚本；构建产物、样本、全量结果都在仓库之外或 `artifacts/` 下。

### 1.2 依赖规则

| 项目 | 可以引用 |
|---|---|
| Model | 无 |
| Native | Model |
| Targets.* | Native、Model |
| Runtime | Native、Model |
| Managed | Model |
| Kernel | Native、Runtime、Managed、Model |
| Recovery | Kernel 及其依赖 |
| Input | Native、Runtime、Model |
| Output | Managed、Model |
| Pipeline、Cli | 全部 |

保证方式有三层：

1. **项目引用**。Kernel、Recovery、Output 的工程文件里没有任何 `Targets.*`。
2. **契约检查**。每层出口的检查器核对词汇，在测试和全量里都运行。
3. **架构测试**。扫描程序集：目标相关的类型名（寄存器、节名、指令字）不出现在 Targets 之外；运行时结构的偏移数值不出现在 `spec/` 之外。

### 1.4 本地文件与私有数据

- 本地文件统一命名为 `*.local.*`，由 Git 忽略；本地的环境与路径说明写在仓库根的 `AGENTS.local.md`。
- 样本、语料的构建产物、全量结果放在仓库之外或 `artifacts/` 下。
- 具体样本的名称、业务标识、本机路径不进入仓库里的代码、测试和文档。

### 1.5 代码约定

- 逻辑代码不用 `try/catch` 隐藏错误；外部读写只捕获明确的异常。
- 恢复逻辑不读环境变量，不直接写控制台；诊断经统一的接收器输出。
- 逐方法恢复不使用可变的静态状态；全局事实只读、可并发访问。
- 注释与文档用简洁、客观的中文，写当前行为和必要的原因，不记录日期、轮次和过程。

## 2. 核心概念怎样建模

### 2.1 项

- 不可变、驻留。每个方法一张项表，是构造项的唯一入口；规范化在入口里完成，外部不能绕过它直接构造。
- 相等就是引用相等。
- 位宽是项的属性。未知是一种项，带原因。
- 规范化的每条规则配一条性质测试：对随机输入，规范化前后求值结果相同。

```csharp
public abstract class Term { public int Width { get; } }

public sealed class TermTable
{
    public Term Constant(ulong value, int width);
    public Term Apply(Operator op, params Term[] operands);   // 规范化在这里
    public Term Slice(Term source, int low, int width);
    public Term Concat(params Term[] lowToHigh);
    public Term Read(Location location, Definition clobber);
    public Term Unknown(int width, Reason why);
}
```

### 2.2 程序快照

- 一个方法是一张不可变的图：块、块入口的合流、块内按次序的写入与事件、终结。
- 变换接收一个快照，产出一个新快照，不就地修改。
- 调用点、合流、帧对象的身份是独立的标识，跨快照保持；复制产生新标识并记录来源。
- 查询结果按快照缓存，快照换了就失效，不需要手工通知。

### 2.3 状态模型

- 区域的划分只有一个函数：给定地址项，回答它属于哪一类、哪个区域。
- 别名判定只有一个入口，三值：必然相同、必然不同、不能判定。
- 每个区域一条定义链；“某次读取最近的可能改写是谁”是一个查询。
- 调用的效果摘要经一个接口取得，三个来源（登记表、已恢复方法的摘要、未知上界）在接口后面。
- 性质测试：别名知识增加后，任何读取的“最近的可能改写”不晚于之前。

### 2.4 运行时操作登记表

一项就是一条数据，各层都从这里读，不各自判断：

| 栏 | 内容 |
|---|---|
| 输入 | 每个输入的用途（值、位置、被指内容）与类型 |
| 结果 | 类型与有效位宽 |
| 内存效果 | 整体效果，以及经指针实参的具体读写 |
| 可观察性 | 可观察、不可观察、幂等（附它建立的标志） |
| IL 写法 | 下降成什么 |

新增一种运行时操作是新增一项，不改各层的代码。

### 2.5 路径事实

- 事实挂在边上，沿控制流传播，合流处取交。
- 对外只有一个判定：给定条件项和某一点的事实，回答真、假或不能判定。
- 检查的吸收、守卫的消去、活跃性、等价引擎都调用这个判定。

### 2.6 查询

```csharp
public readonly record struct Outcome<T>(T? Value, Reason? Why);

public interface IQuery<TKey, TValue>
{
    Outcome<TValue> Compute(QueryContext context, TKey key);
}
```

- 查询是纯函数：不改快照，不改别的查询的结果，结果不依赖被调用的次序。
- 查询经上下文取用别的查询，上下文负责记忆与依赖记录。
- 失败返回原因；原因引用它依赖的失败，形成链。
- 需要迭代的一组查询写成显式的不动点组：声明单调量、步数上限；到上限返回洞。
- 不允许的写法：以语句对象为键在查询之外保存状态；为了让某个查询好算而改写快照。

### 2.7 等价引擎

- 输入：两段代码（各自的快照、入口、出口集合）、入口处两侧的对应关系、入口事实。
- 输出：成立，或第一处不等价的联合路径及其种类。
- 两侧各由一个解释器在快照上推进，产生事件；引擎只比较事件、堆和结局，不关心两侧的形状。
- 预算按步数计。
- 引擎只有一个语义定义；内联、守卫、finally、复核、语料对照是它的不同驱动。

### 2.8 目标描述

```csharp
public interface IImage            // 文件格式
{
    // 节与段、重定位、导入导出、按地址读取、函数范围、try 区间
}
public interface ILifter           // 指令集
{
    LiftedFunction Lift(IImage image, FunctionRange range);
}
public interface IAbi              // 调用约定
{
    SlotAssignment Classify(CSignature signature);
    // 被调保存集合、栈实参区与入口帧基址的关系
}
public interface IPlatform         // OS 约定
{
    // 线程指针、栈保护槽、导入符号的含义
}
public sealed record Target(
    IImage Image, ILifter Lifter, IAbi Abi, IPlatform Platform,
    CompilerProfile Compiler, RuntimeSpec Runtime);
```

- 异常模型把各自的表归一成“调用点区间到处理入口与种类”，经 `IImage` 或单独的接口给出。
- 运行时函数的 C 原型与托管方法的 C 层签名走同一个 `Classify`。
- Kernel 以上只见到“第 i 个实参”和抽象槽位。

### 2.9 洞

洞是一条记录：所在的层、位置、没能换掉的项或没能成立的证明步骤、原因链、是否派生。报告、普查和归因都读这条记录，不解析文本。

## 3. 一个事实该放在哪

| 要表达的事实 | 放在哪 |
|---|---|
| 一条指令的语义 | 指令集的提升器 |
| 寄存器与实参的对应、结构体怎样传 | ABI 的分类函数 |
| 节名、重定位、异常表的格式 | 文件格式、异常模型 |
| 栈保护、线程指针、libc 与 libm 的符号 | OS 约定 |
| 运行时结构的一个字段 | `spec/` 的布局数据 |
| 一个运行时函数是什么、怎样认出它 | 运行时函数目录 |
| 一种运行时操作的输入、效果、可观察性、IL 写法 | 登记表的一项 |
| 某次读取读的是运行时结构的哪个字段 | 值的命名：按规格和项的种类 |
| 一种新的守卫或惰性初始化 | 登记表里标为不可观察或幂等，并指明它的标志；不写识别规则 |
| 一种新的检查 | 条件抛出，登记异常种类 |
| 一种位搬运或位技巧 | 项的规范化，配性质测试 |
| 两次读取是否同值 | 读取的身份；缺的是别名知识就补别名判定 |
| 地址对应的 IL 位置 | 位置查询 |
| 不同类型共用位型 | 表示链 |
| 多次机器访问构成一次 IL 访问 | 整体访问查询 |
| 一个值的 IL 类型 | 类型查询；原子的类型来自定义 |
| 两段代码是否等价 | 等价引擎；不另写路径比较 |
| 内联证明不成立 | 看诊断里第一处不等价，补规范化、路径事实或候选索引；不加出口分类 |
| 编译器造成的新变形 | 先查清现有机制为什么没有吸收它；是机制的缺口就补机制 |
| 调用目标 | 分派的查询；目标只增不减 |
| 反编译器不认的形态 | 表示层 |
| CIL 能表达而 C# 不能表达的写法 | 输出的合法性改写，写明语义差别 |
| 预算与阈值 | 编译器剖面或该机制的预算表，附语料用例 |

答不出“放在哪”时，先不写代码，回到设计第 12.2 节的第 2 步。

## 4. 流程

### 4.1 一个任务怎样做

1. **定范围**：任务对应哪条契约或哪个模型的哪一段，验收是什么。
2. **找依据**：生成器的哪个模板或哪种变换；写出模型回答的问题与正确性标准。
3. **做用例**：语料里加最小用例，先让指标在它上面失败。
4. **实现**：按第 3 节的表落位。
5. **验证**：按 4.2 的档位。
6. **报告**：按 4.4 的格式。
7. **同步文档**：改了契约先改设计；新增了扩展点更新本文第 3 节；检验了假设把结论记回设计第 12.4 节。

### 4.2 验证的三个档位

| 档位 | 内容 | 何时 |
|---|---|---|
| 快速 | 构建、性质检查、契约检查、语料子集 | 每次改动，几分钟内 |
| 定向 | 语料全量、主样本上与任务相关的方法清单、CIL 有变化的方法做执行对照 | 提交前 |
| 全量 | 主样本全部方法与全部度量，对比上一次全量的状态变化和每层摘要 | 改了共享机制之后；每一步的出口 |

- 命令保持短，只看与任务相关的指标。
- 已有结果直接用，不为凑数字重复运行；跑了全量就不再跑子集。
- 全量在后台跑。

### 4.3 并行协作

- 每个执行者一个工作树和分支，按项目划分所有权。
- 公共契约先行：原生 IR、Kernel 的公共类型、托管方法体的改动先合进主线，其他任务再跟进。
- 不引入跨任务共享的可变上下文。两个任务都需要同一个判断时，把它上移成查询。
- 合并之前过快速档与定向档。
- 与主线冲突时以主线为准重新合入。

### 4.4 提交与报告

提交说明写明这次改动的形式和依据：

| 形式 | 含义 |
|---|---|
| 补事实 | 元数据、布局、ABI、规格里本来存在而没有读出的信息 |
| 补定义 | 模型对某种操作没有定义；定义对所有输入成立 |
| 补等价 | 两种表示语义相同而模型只认一种；以语义证明为依据 |
| 补逆变换 | 编译器的一种变换没有对应的逆；以可检验的证据成立 |
| 补机制 | 横切机制本身的能力 |

报告按这个次序，不适用的省略，没有验证的如实说明：

1. **定位**：现有产物与预期，问题在哪一层。
2. **分析与修复**：原因、适用的模式、实现方式。
3. **实际结果**：重新生成的产物，剩下的缺口。
4. **通用性**：另一处同类问题的依据与前后对比。
5. **验证**：做了哪一档、指标变化、没有验证的边界。

### 4.5 不允许的做法

- 按方法名、类型名、地址或样本里的具体常量分支。
- 为让某个样本通过而放宽判定、跳过检查或补默认值。
- 在下游掩盖上游的错误。
- 把失败改写成另一种标记，或写执行不到的占位语句。
- 放宽执行对照、语料对照的比较标准而没有独立依据。
- 为编译器优化造成的变形写形态规则。

出现设计第 12.3 节的任何一条停止信号时，停下来报告，不继续加规则。

### 4.6 完成的定义

- 契约检查通过，快速档与定向档通过。
- 有对应的语料用例。
- 没有新的执行对照不一致；写出数下降时逐个说明原因。
- 剩余的缺口是带原因的洞。
- 文档已同步，报告已给出。
