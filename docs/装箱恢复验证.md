# 装箱恢复验证

## 恢复规则

- 从 `il2cpp_value_box` 的已识别目标和第一个参数的 `TypeInfo` 确认类型；第二个参数指向被复制的值。
- 值类型必须闭合、布局已知且允许装箱。按完整类型读取，在原调用位置输出 `box`，不能把枚举改成其底层整数，也不能把数据地址当作对象。
- 栈对象和返回缓冲区沿用所有路径上的初始化检查。漏写、部分写入、后写先读以及元数据与数据类型不符都拒绝恢复。
- 装箱后修改原值不会改变已装箱的副本；重复装箱保持独立对象身份。结构体中的对象字段仍保存原引用。
- nullable 无值得到 `null`，有值得到内部值的装箱对象。
- 若装箱类型有静态构造函数，先固定源地址并分配装箱对象，显式初始化类型，再读取数据填入同一个对象。nullable 在初始化之前检查 `HasValue`，有值时只初始化内部类型，并在初始化后读取 `GetValueOrDefault`；不能重新判断空值而改变已经选择的原生分支。
- 原生辅助函数也接受引用类型：此时读取原引用，不创建新对象。
- 普通调用保存对象结果，尾调用直接返回；没有使用返回值也保留调用位置的 CIL 装箱指令。

当前输入中，导出 `0x49c8724` 跳转至 `0x49f76b8`。主体包含引用读取、nullable 空值分支、值数据复制及写屏障；分配路径 `0x49f7a88` 对 nullable 选择内部类型，并调用类初始化主体 `0x49c4710`。后者也是 `il2cpp_runtime_class_init` 导出 `0x49c871c` 的目标。单独的 CLR `box` 不保证这些初始化副作用。这些是当前 ARM64 二进制证据，输入哈希同[静态字段恢复验证](静态字段恢复验证.md)。

## 执行检查

合成机器 IR 使用真实枚举 TypeInfo 检查栈复制、引用读取、尾调用、未使用结果及初始化反例。托管值检查另覆盖整数、布尔、单/双精度浮点、`IntPtr`、nullable 和含引用结构体。浮点覆盖负零、最小非正规数、无穷和 NaN 位型。

以上方法执行生成的 CIL，再将 ILSpy 输出的 C# 重新编译执行。nullable 和含引用结构体在此是托管输出检查，不代表任意原生 nullable 栈构造都已恢复。

合成静态构造函数分别修改待装箱的值、清空有值 nullable、抛出异常。检查源值在初始化后才复制、空值不初始化、一次性执行及异常缓存。分配后的写回使用 CIL 的 `unbox` 与 `stobj`；目标引用库提供公共 `Unsafe.Unbox<T>(object)` 时，源码视图将对应可写拆箱左值还原为该接口，避免生成非法强制转换赋值。

真实方法 `PathUtility.GetCombinePath`（`0x55d295c`）恢复整个方法体：

- `File`、`AssetDataBase` 两种输入创建字符串数组，调用真实恢复的 `GetSlashCombinePath`（`0x55d2ac4`）。
- 其他枚举值装箱并使用元数据中的格式字符串，调用 `Debug.LogError`，最后读取 `String.Empty`。
- 检查正常路径、多段与中文路径、反斜杠、空引用；错误路径检查枚举整数边界、一次日志、空字符串返回及日志抛异常时的行为。

真实方法的 CIL 和重新编译后的 C# 均执行检查。依赖映射使用当前 CLR 的路径和字符串库，日志使用记录宿主；没有手写替代恢复方法体，没有加载 Unity，也没有验证 Android/Windows 路径库的全部差异。

既有栈对象与返回缓冲区回归同时覆盖分支、循环、共享引用、边界值及真实调用者执行。

`Grid2DPosition.ToString`（`0xa460d10`）恢复两次 `sbyte` 装箱与字符串格式化，CIL、重新编译的 C# 各穷举两个字段的全部 65,536 种组合，验证无符号机器读取之后仍按元数据保留负数。

## 当前边界

装箱结果目前按 `object` 传播，尚未利用其来源恢复接口或 `ValueType` 目标转换。栈初始化仍要求完整字节范围，结构体填充和 nullable 分支构造可能被拒绝；原生 `IntPtr` 栈对象仍受指针分类限制。泛型布局、私有字段访问和未知地址继续沿用已有约束。原生拆箱辅助调用、对象分配与构造合并尚未接通。

分配与初始化顺序按 CIL 指令检查，尚未注入资源耗尽来验证分配失败。当前目标二进制裁剪后的 `Unsafe` 没有 `Unbox`；需要这种初始化写回的 CIL 可以保留，但对该引用集的 C# 往返仍有接口缺口。合成初始化往返检查使用提供该接口的当前 CLR，不据此声称原目标库也已支持。
