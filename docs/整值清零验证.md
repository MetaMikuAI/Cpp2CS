# 整值清零验证

## 恢复范围

同一基本块中，连续的零值字段写入若精确覆盖已知结构体，可恢复为整个值的 `default` 赋值。允许同一对象中两个结构体的字段交错写入；每个完整结构体在其第一次写入处清零。

- 只处理稳定的对象、托管引用、参数、局部变量及栈存储。逐层核对字段身份、偏移、类型和位宽。
- 必须完整覆盖且无重叠，不跨填充，不解释引用、指针、未知或重叠布局。
- 不跨读取、调用、控制流、非零写入或其他可能别名的根引用。
- 不能借合并绕过只读根字段的写入限制；只允许其声明类型构造中的 `this` 初始化。
- 保留其他语句和恢复依赖。只读结构体的成员可以被整体初始化，不再逐项赋值。

这是已知字段的单线程值恢复；原生宽写入的跨线程原子性、volatile 和 Unity 运行时行为仍未验证。

## 执行验证

合成方法经过托管方法体、CIL 和 C# 重编译执行，覆盖交错写入、`ref`、按值参数、局部变量、栈存储、重复清零、空对象异常及范围外字段不变。部分、重复、非零、错误位宽和未知布局写入保持原样；读取、调用、控制流及其他根引用会阻断合并。

真实 `Sekai.Mysekai.MysekaiBlueprint3DPreview` 的两个 `LoadTarget` 字段位于 `0xdc` 和 `0xe8`，各占 12 字节，内部三个只读字段偏移为 `0/4/8`。

| 方法 | 原生地址 | 写入证据 |
| --- | --- | --- |
| `OnEnable` | `0x56f956c` | 三次 64 位清零，顺序为 `0xe4`、`0xdc`、`0xec` |
| `Initialize` | `0x56f957c` | 按 `0xe4`、`0xdc`、`0xe8`、`0xf0` 清零，宽度为 32/64/64/32 位 |
| `Dispose` | `0x56ee0e4` | 先读取预览对象，再按 `OnEnable` 的顺序清零，最后调用 `Release` |

三个完整原生方法体恢复成 CIL，再反编译为 C#、重编译并执行。验证两个值清零、重复调用、范围外字段不变；`Release` 观察到清零后的状态，空接收者及调用失败均保留异常和此前写入。

测试使用匹配的只读结构体宿主和记录 `Release` 的依赖，没有手写替代目标方法体，也没有加载 Unity。

既有合并字段写入的 bool、浮点位型、别名、嵌套引用及真实材质构造链回归通过。

两份变化源码均在主程序集：上述预览类型的三个方法，以及 `MysekaiTalkUtility` 的一个 `out` 参数清零分支。后者通过全量恢复和源码编译检查，未单独执行其完整业务方法。其余目标源码逐字节一致，`Sekai.Api` 无新增或回退。
