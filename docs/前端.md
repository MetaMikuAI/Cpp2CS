# 前端接口

前端把一个方法的原生代码变成**快照**（设计 7.1）。它了解文件格式、指令集、调用约定与异常表；它不了解运行时，也不做恢复层面的判断。本文说明前端构造快照的接口和必须遵守的约定。

前端所在的程序集只引用 `Cpp2CS.Snapshot`。下面提到的类型都在这个程序集里。

## 1. 分工

前端做的事：

- 划分基本块，把寄存器、标志位、子寄存器变成值（项），把跨块的值变成块参数；
- 把每条指令的计算写成项，把内存访问、调用、动态栈分配写成出现；
- 按调用约定把寄存器映射到抽象槽位；
- 识别跳转表、展开出口、不返回的调用这些**指令集与文件格式层面**的结构。

前端不做的事：

- 不识别运行时函数、元数据、类、字段、方法：调用目标只是一个地址，访问的位置只是一个地址；
- 不消除栈上的读写，不判断寄存器是否被恢复，不合并条件，不化简表达式；
- 不猜。识别不了的结构（例如目标未知的间接跳转）让这个方法不产出快照，并报告原因。

## 2. 接口

```csharp
var snapshot = new SnapshotBuilder(pointerBits: 64);   // 可以传入已有的 TermPool
TermPool terms = snapshot.Terms;

Term EntryParameter(Slot slot, int width);             // 声明入口参数
void SetReturnSlots(params (Slot, int Width)[] slots); // 声明返回行
BlockId Entry { get; }                                 // 入口块
BlockId Block(params int[] parameterWidths);           // 声明块及其各参数的位宽
Term Parameter(BlockId block, int index);

Term Read(BlockId block, Term location, int width, ulong address = 0);
void Write(BlockId block, Term location, Term value, ulong address = 0);
ImmutableArray<Term> Call(BlockId block, Term target, (Slot, Term)[] arguments, (Slot, int Width)[] results, ulong address = 0);
ImmutableArray<Term> CallPrimitive(BlockId block, int primitive, (Slot, Term)[] arguments, (Slot, int Width)[] results, ulong address = 0);
Term StackAllocate(BlockId block, Term size, ulong address = 0);

void Terminate(BlockId block, Terminator terminator);  // Single、Branch、Switch、Invoke
void Jump(BlockId block, BlockId target, params Term[] arguments);
void Return(BlockId block, params Term[] values);

MethodSnapshot Build();                                // 校验并冻结；不满足契约时抛出 FlowException
```

出现按追加的次序排在块里。`address` 是原生地址，只用于诊断，不作身份，不进入摘要。

终结与出口：

| 写法 | 含义 |
|---|---|
| `Terminator.Single(exit)` | 无条件离开 |
| `Terminator.Branch(condition, whenTrue, whenFalse)` | 条件是 1 位的项；为 1 走前一个出口 |
| `Terminator.Switch(selector, exits)` | 选择子等于 i 走第 i 个出口；最后一个出口是其余取值的去向 |
| `Terminator.Invoke(normal, unwind)` | 块内最后一个出现是调用；正常返回走前一个出口，展开走后一个 |
| `Exit.To(block, arguments…)` | 去往一个块，整行实参与该块的参数逐项对应 |
| `Exit.Return(values…)` | 方法返回，各值与返回行逐项对应 |
| `Exit.NoReturn` | 块以一次不返回的调用结束 |
| `Exit.Trap` | 陷阱指令 |

边的身份是（源块，出口序号）。同一个源块到同一个目标块可以有多条边，各自带自己的实参行。

## 3. 项

值都是项，由 `TermPool` 构造。项池在构造时规范化并驻留：移位、掩码、扩展、截断会变成切片与拼接，比较的方向与严格性会归一。前端按指令的语义直接构造，不要自己化简，也不要依赖构造出来的项的具体形状。

| 构造 | 说明 |
|---|---|
| `Constant(long, width)`、`Bits(UInt128, width)` | 常量，位宽不超过 128 |
| `Undefined(width)` | 未定义的位：调用之后被破坏的寄存器、指令未定义的结果、填充 |
| `Slice(x, offset, width)`、`Concat(low, …, high)` | 切片与拼接，拼接从低位到高位 |
| `ZeroExtend`、`SignExtend`、`Truncate` | 位宽的变化 |
| `Add`、`Sub`、`Mul`、`Neg`、`Divide(op, x, y)` | 整数运算，回绕；`Divide` 的 op 是 `UDiv`、`SDiv`、`URem`、`SRem` |
| `And`、`Or`、`Xor`、`Not`、`Shl`、`LShr`、`AShr` | 位运算；移位量与被移位的值同宽 |
| `Eq`、`Ne`、`Ult`、`Ule`、`Ugt`、`Uge`、`Slt`、`Sle`、`Sgt`、`Sge` | 比较，结果 1 位 |
| `Select(condition, whenTrue, whenFalse)` | 条件选择（`csel`、`cmov`） |
| `Operation(op, width, operands…)` | 其余运算：进位与溢出、高半乘积、位计数、浮点 |
| `Opaque(code, width, operands…)` | 目标特有的纯运算，以代码区分；代码由目标描述定义 |

浮点值就是它的位型。`Entity` 与 `Attribute` 由事实层使用，前端不构造。

## 4. 约定

**块与值。** 每个块只使用自己的参数和块内此前产生的值，以及常量。入口参数只在入口块可见。需要跨块的值经边上的实参行传给目标块的参数。前端不必求最小的参数表：把目标块可能用到的寄存器都列为参数是允许的，只要进入同一个块的各条边给出的实参个数与位宽一致。

**入口块。** 入口块没有参数，也不能有入边。原生代码跳回第一条指令时，在入口块之后另设一个块作循环头。每个块都必须从入口可达。

**寄存器与标志位。** 快照里没有寄存器名，也没有标志寄存器。条件由比较直接写成 1 位的项（`cmp w9, w1; b.ls` 写成 `Ule(w9, w1)`）。写子寄存器按指令集的规则写成项：写入时清零高位的是零扩展；保留高位的是新值与旧值高位的拼接。

**内存。** 所有内存访问都是出现，栈上的也是。地址是指针位宽的项，数据小端，位宽按位计。一条指令访问几个位置，就写成几个出现，按指令语义的次序。

**槽位。** 入口参数、调用的实参与结果、返回行都按抽象槽位给出：

| 槽位 | 含义 |
|---|---|
| `Integer i`、`Vector i` | 调用约定里第 i 个整数（指针）、浮点（向量）实参与结果寄存器 |
| `IndirectResult` | 间接结果的地址 |
| `StackPointer` | 栈指针。经栈传递的实参是相对它的内存读取 |
| `ReturnAddress` | 返回地址：入口处在链接寄存器里的值；返回行上是实际返回到的地址 |
| `Preserved i` | 第 i 个被调方保存的寄存器 |
| `ThreadPointer` | 线程指针 |
| `Unwind i` | 展开出口上由运行时给出的值（异常对象、选择子） |
| `Managed i` | 只用于模板一侧，前端不使用 |

同一个槽位在入口处只声明一次。没有声明的槽位不能使用。

**调用。** 目标是一个项：直接调用是常量地址，间接调用是算出来的值。前端不知道被调方有几个参数，所以把调用约定里各实参槽位此刻有定义的值都列出，并列出栈指针。结果按返回值槽位各列一个。调用之后，调用约定规定由调用方保存的寄存器是 `Undefined`，由被调方保存的寄存器保持原值。尾调用写成一次调用加一个返回出口，返回行取这次调用的结果。

**不返回的调用。** 调用之后没有后继指令（它是函数的最后一条指令，且不是尾调用）时，块以 `Exit.NoReturn` 结束。除此之外的调用都按会返回处理；“某个函数不返回”这样的知识属于规格，不属于前端。

**展开出口。** 调用点在异常表里有着陆点时，这次调用必须是块的最后一个出现，块以 `Terminator.Invoke` 结束。运行时在着陆点给出的值是这次调用的 `Unwind` 槽结果，经展开出口的实参行传给着陆点的块。

**返回。** `SetReturnSlots` 声明返回行。行里依次列出：各返回值槽位，`ReturnAddress`（实际返回到的地址），`StackPointer`，各 `Preserved` 槽位在返回时的值。前端只列出值，不判断它们是否等于入口处的值。

**跳转表与陷阱。** 能在指令集层面确认表的位置与项数的间接跳转写成 `Terminator.Switch`。陷阱指令写成 `Exit.Trap`。

**原语。** 原子操作、内存屏障、系统调用等写成 `CallPrimitive`，代码由目标描述定义并登记到规格。

## 5. 校验与摘要

`Build` 检查：每个块都已终结且可达；每条边的实参个数与位宽同目标块的参数一致；入口块没有入边；每个值在使用处可见；地址是指针位宽；分支条件是 1 位；带展开出口的调用与不返回的出口之前是一次调用。任何一条不满足，`Build` 抛出 `FlowException`，其中列出全部违反之处，不产生快照。

快照带一个内容摘要（SHA-256）。它只取决于图的内容，与项池里项的构造次序、原生地址无关。

快照构造之后不可变。每个出现、每条边、每个内存版本都有稳定的身份：`OccurrenceId(块, 序号)`、`EdgeId(源块, 出口序号)`、`MemoryVersion(块, 定义)`。内存版本由快照算出：每次写入、每次调用产生一个版本，块入口的版本随入边传入。

## 6. 示例

下面是一个读实例字段的方法在 ARM64 上的代码，以及按上面的约定构造的快照。完整的代码在 `tools/ForwardCheck/SnapshotExample.cs`。

```text
    str  x30, [sp, #-0x10]!
    cbz  x0, raise
    ldr  w0, [x0, #0x10]
    ldr  x30, [sp], #0x10
    ret
raise:
    bl   il2cpp_codegen_raise_null_reference_exception
```

```csharp
var snapshot = new SnapshotBuilder(pointerBits: 64);
var terms = snapshot.Terms;
var integer0 = new Slot(SlotKind.Integer, 0);
var stack = new Slot(SlotKind.StackPointer, 0);
var link = new Slot(SlotKind.ReturnAddress, 0);

Term x0 = snapshot.EntryParameter(integer0, 64);
Term sp = snapshot.EntryParameter(stack, 64);
Term x30 = snapshot.EntryParameter(link, 64);
snapshot.SetReturnSlots((integer0, 64), (link, 64), (stack, 64));

BlockId load = snapshot.Block(64, 64);     // x0，帧地址
BlockId raise = snapshot.Block(64);        // 帧地址

Term frame = terms.Add(sp, terms.Constant(-0x10, 64));
snapshot.Write(snapshot.Entry, frame, x30);                                   // str x30, [sp, #-0x10]!
snapshot.Terminate(snapshot.Entry, Terminator.Branch(terms.Eq(x0, terms.Zero(64)),
    Exit.To(raise, frame), Exit.To(load, x0, frame)));                        // cbz x0, raise

Term value = snapshot.Read(load, terms.Add(snapshot.Parameter(load, 0), terms.Constant(0x10, 64)), 32);
Term restored = snapshot.Read(load, snapshot.Parameter(load, 1), 64);         // ldr x30, [sp], #0x10
snapshot.Return(load, terms.ZeroExtend(value, 64), restored,
    terms.Add(snapshot.Parameter(load, 1), terms.Constant(0x10, 64)));        // ret

snapshot.Call(raise, terms.Constant(0x448408, 64), [(stack, snapshot.Parameter(raise, 0))], []);
snapshot.Terminate(raise, Terminator.Single(Exit.NoReturn));

MethodSnapshot result = snapshot.Build();
```

这段代码里没有“判空”“字段”“抛出”这些词。把 `cbz` 认成 `ldfld` 的空检查，把保存与恢复 `x30` 认成不可观察的帧操作，是事实层与解释层的事。

## 7. 实体与元数据模型

快照里没有实体。类、方法、字段、字符串由事实层引入，写成实体项：`TermPool.Entity(EntityRef, width)`。

`EntityRef(Kind, Key)` 是不透明的身份。内核只比较它是否相等，并原样传递；`Key` 的取值空间由元数据模型分配：模型里每个类型、方法、字段、字符串有一个稳定的编号，`Key` 就是这个编号。

模板一侧经 `Cpp2CS.Kernel.Forward.IMetadataView` 取得元数据：方法的签名与分派方式，字段的类型、所属的类与偏移，类型在求值栈上的类别与存储位宽，以及它们的实体身份。这个接口以后由元数据模型上的一个适配器实现。对接时只有一条要求：事实层引入的实体与 `IMetadataView` 给出的实体使用同一个 `Key` 空间，这样原生一侧认出的字段与模板一侧引用的字段才是同一个项。值类型的大小与字段偏移同样以模型给出的为准。

核对工具 `tools/ForwardCheck` 里有一个直接读托管程序集的 `IMetadataView` 实现，只供正向核对使用。

## 8. 稳定性

`SnapshotBuilder`、`TermPool` 的各构造方法、`Terminator`、`Exit`、`Slot` 与 `SlotKind`、`Op` 是前端依赖的公开面。对它们只增加，不改变已有成员的含义。
