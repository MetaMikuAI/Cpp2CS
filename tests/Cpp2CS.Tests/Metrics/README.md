# IL 对照指标

先构建解决方案，再调用 `il-compare` 包装命令；构建和运行按本机约定持有重任务锁。`DOTNET` 指向 SDK 的 dotnet 可执行文件。包装命令使用 Debug/net10.0 下已构建的检查程序，不隐式构建。

```sh
python3 tests/Cpp2CS.Tests/Metrics/il-compare reference.dll tested.dll methods.json output.json 32 10000 0
```

四个必选参数依次为参考程序集、待测程序集、真值方法表、输出文件。可选参数依次为用例数、每个用例的总 IL 步数上限、首个种子。预算由两侧执行和参考侧异常计划的试运行共用；元数据加载、输入合成和抽象外部调用不按 IL 指令计。解释器另有固定的调用深度上限，单独报告 `CallDepthBudget`。

方法表沿用真值 `methods.json`。工具筛选参考程序集文件名对应的行，核对 MVID、MethodDef 标记及完整签名。待测方法按声明类型、名称、形参和返回类型、泛型参数位置与元数、调用约定精确匹配；不使用待测方法标记。

代码入口为 `IlMetrics.Compare`，接受 Cecil 模块、参考方法序列和 `MetricOptions`；单方法重载接受两个 MethodDefinition。`IlMetrics.Json` 生成排序后的 JSON。

JSON 格式版本为 1，UTF-8、LF、递归按序排列对象键，无时间戳与机器路径。方法数组保留请求次序。顶层为 `format_version`、`options`、`methods`、`summary`：

- `methods`：完整身份、四态状态、有限枚举原因、差异或原因说明、首个差异种子、完成数、NaN 跳过数和覆盖。
- `coverage`：两侧完成的用例中参考侧的指令总数、到达数、占比、未到达偏移，以及每条条件分支的方向数组。普通分支顺序为未跳转、跳转；switch 为各索引，最后一项为默认出口，即使多个索引指向相同目标也分别计数。覆盖不包含异常计划试运行。
- `attempted_coverage`：还包括未完成和 NaN 跳过用例的参考侧执行，用于改动处是否到达的诊断；不用于“一致且覆盖完整”的计数。
- `summary`：各状态数量与占总方法数比例、无法判定原因分布、完整覆盖/缺分支/仅缺指令三类一致方法数量、受 NaN 影响的方法数。

参考没有方法体时无法判定；参考有体而待测缺方法或缺体时没写出。解释器拒绝 NaN 的用例跳过；其余用例全部完成且相同、并至少完成一个时一致。差异用例计入完成数，首次差异立即返回。其他无法判定立即返回，保留此前完成数。结果不做任何额外的浮点或字节相等归一化。

## 检查

检查运行器自动发现 `il-metrics-check`、`il-metrics-corpus`。后者需要 `CPP2CS_CORPUS` 和 `CPP2CS_CORPUS_TRUTH`，缺失时说明并跳过。选择 cases.json 涉及程序集的全部方法，并在其余 methods.json 行中按 `floor(i*N/k)` 等距抽取 k 个方法（日常 k 为 200；`CPP2CS_IL_METRICS_LIBRARY` 可指定，量基线数字时用 2000，约九分钟），包含泛型定义和无体方法，不按可解释性挑选。

每个方法每类取第一个合法候选位置，单独生成整数常量加一、分支取反、加减互换、移除字段写入、移除调用、返回默认值、交换同类型的两个实参。不具备候选的数量单列，不计入发现率分母。保持栈平衡；不写回输入程序集。每个改动使用自己的两侧常量提示，报告其实际参考执行覆盖，而非假设输入与未改动的自对照完全相同。

定向报告默认写入忽略的 `artifacts/il-metrics.local.output/`，可用 `CPP2CS_IL_METRICS_OUTPUT` 改位置：`comparison.local.json` 为上述报告，`sensitivity.local.json` 含逐改动结果及按种类汇总。用时只打印控制台，不进入可复现 JSON。

未发现分类：只有完成对照且位置未到达才记 `NotExecuted`；其余记 `Other`，包括解释器无法判定和执行到但未影响当前观察的改动。没有等价证明时不记 `Equivalent`，因此该计数为零不表示不存在等价改动。灵敏度是有限输入、当前观察模型和候选生成方式共同决定的性质；不是所有错误的发现概率，也不是全路径等价证明。

灵敏度回归界：已到达改动的总体发现率至少 40%，每类至少 15%。校准时包含未到达和无法判定的全部候选中，总发现率约 43%，最低类别约 19%；以五个百分点网格向下留余量。断言分母改用所有实际到达位置，仍包含无法判定，不按当前是否可解释筛选。该界用于防止明显退化，不宣称这些比例足以用于恢复结果验收。

## 类型对应的口径

模块加载只建立身份；比较在入口调用、实际执行的成员访问、类型操作、输入对象合成和布局请求时检查对应。无关类型或未调用的非虚方法不阻断当前方法。输入提示扫描不触发成员检查。失败为 `TypeMismatch`，说明类型及差异种类；输入合成不覆盖这一原因。

- 类型属性、基类、接口、泛型参数属性与约束必须对应。
- 实际调用的方法按声明类型、名称、参数和返回类型、泛型位置与元数、调用约定对应，并核对方法属性、实现属性与泛型约束。虚分派另检查候选槽及显式实现。未调用的非虚方法列表与次序不参与比较：解释器的直接调用按方法身份解析，不按 MethodDef 行号执行。
- 使用对象或字段布局时，字段名字、类型、全部属性（含静态性）、次序、显式偏移、常量及 RVA 数据必须一致，同时核对 packing 与 class size。当前解释器按字段次序分配紧密存储，因此不忽略字段次序；无法支持的显式布局仍单独报解释器限制。
- 泛型参数按位置对应，不使用参数名称。依据是 CLI 签名中 VAR/MVAR 的参数序号，且 `CecilModel.Type` 和方法索引都按位置代换。
- 自定义修饰符、安全性与封送标记暂不忽略。无法证明不影响执行的差异仍判为不对应；本工具不以 il2cpp 丢失信息为由统一删除修饰符。Unity 2022.3 的 `il2cpp-runtime-metadata.h` 中 `Il2CppType` 的修饰符存储被注释掉；生成 C++ 的 volatile 访问仍有 `il2cpp_codegen_memory_barrier`，因此基础类型相同不足以证明执行语义相同。

外部调用继续沿用解释器的抽象模型；本检查不证明依赖程序集整体等价。

`type-metadata-audit` 在已有端到端产物上输出 `types.local.json`，保留各类型的原始属性、基类、布局、字段列表与方法列表差异。普查不采用上述按需筛选，计数单位为“类型 × 差异类别”。需要 `CPP2CS_CORPUS`，缺失时跳过。

带指令前缀的调用与字段写入不生成删除或交换变异，避免把前缀留给不合法的后继指令。
